# Tools and Technologies

## Overview

This document describes the tools and technologies used throughout the API Testing projects in this repository.

Each tool is selected based on its role in the API testing workflow, from API documentation and manual testing to automation, test management, and documentation.

---

| Category | Tool |
|----------|------|
| API Testing | Postman |
| API Documentation | Postman API Documentation |
| Test Management | Qase.io |

# Tools

## Postman

**Purpose**

Postman is the primary tool used for API testing.

It is used to:

- Send HTTP requests
- Validate API responses
- Test RESTful endpoints
- Create API collections
- Manage environments
- Store variables
- Build automated API tests
- Generate API documentation

Usage within this repository:

- Manual API Testing
- API Automation
- Environment Management
- Collection Management
- Public API Documentation

---

## Postman API Documentation

**Purpose**

Postman API Documentation is used to publish and organize API collections into readable documentation.

It is used to:

- Document API endpoints
- Describe request parameters
- Display request examples
- Display response examples
- Share public API documentation

Usage within this repository:

- API Documentation
- Endpoint Reference
- Project Documentation

---

## Qase.io

**Purpose**

Qase.io is used as the Test Management System.

It is used to:

- Organize Test Suites
- Manage Test Cases
- Execute Test Runs
- Record Execution Results
- Generate Testing Reports
- Track Testing Progress

Usage within this repository:

- Test Management
- Test Execution
- Test Reporting

---

## Git

**Purpose**

Git is used for version control.

It is used to:

- Track project history
- Manage repository versions
- Maintain documentation changes

---

## GitHub

**Purpose**

GitHub hosts the repository and serves as the public portfolio.

It is used to:

- Publish project documentation
- Store testing artifacts
- Showcase QA projects
- Share project history

---

## Markdown

**Purpose**

Markdown is used to create lightweight and structured documentation.

It is used for:

- Project documentation

- Test Scenarios
- Test Cases
- Test Execution Reports
- Bug Reports
- Summary Reports

---

## Visual Studio Code

**Purpose**

Visual Studio Code is used as the primary documentation editor.

- Edit Markdown files

# Technologies

The following technologies are covered throughout the projects.

## REST API

The projects focus on testing RESTful APIs.

Topics include:

- Resources
- Endpoints
- CRUD Operations
- REST Principles

---

## HTTP Methods

The following HTTP methods are tested.

- GET
- POST
- PUT
- PATCH
- DELETE

---

## HTTP Status Codes

Common HTTP status codes validated during testing include:

- 200 OK
- 201 Created
- 204 No Content
- 400 Bad Request
- 401 Unauthorized
- 403 Forbidden
- 404 Not Found
- 405 Method Not Allowed
- 500 Internal Server Error

---

## JSON

JSON is used as the primary request and response format.

Validation includes:

- Request Body
- Response Body
- Data Types
- Response Structure

---

## Authentication

Authentication testing includes:

- Token-based Authentication
- Authorization Header
- Invalid Token Validation
- Missing Token Validation
